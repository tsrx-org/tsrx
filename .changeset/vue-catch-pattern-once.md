'@tsrx/vue-runtime': patch

On the Vue target, a `@try` with `@pending` whose `@catch` parameter pattern throws, such as `@catch ({ response: { status } })` for an error without a `response`, runs that pattern once and passes its error to the next `@catch` out, or to `app.config.errorHandler`, as a `@try` without `@pending` does. When the body threw as it rendered, or an async component rejected after the `Suspense` had resolved, the boundary inside the `Suspense` ran the pattern, and the boundary around the `Suspense`, which renders the same `@catch`, took its error as the body's and ran the pattern again before passing it on. A rejection while the `Suspense` is pending already ran it once. The same applies to what the body's own code throws while the `@catch` shows and the `@try` unmounts, such as a throwing `onBeforeUnmount` the body registered: it now goes on as it does without `@pending`, where before the boundary that was unmounting took it and it was lost. After the `@catch` calls `reset`, what the replaced body still throws stays in that `@catch`, as before.
