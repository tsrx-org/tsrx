Vue components now render their nested children through `props.children`, as on the other targets. vue-jsx-vapor passes nested children as the default slot, so `props.children` was always `undefined` and `<Card><p>child</p></Card>` rendered without the `<p>`. A read of `props.children`, or of a `children` binding destructured from the props parameter or from `props` at the top of the component (`const { children } = props`), now reads the default slot when the caller writes nested children and the `children` prop otherwise; nested children win over the prop, as on React, and a destructured default (`{ children = 'none' }`) applies only when neither is passed. Each place that renders the children renders the slot there, so they are set up when shown and torn down when hidden, as React mounts and unmounts them, and a read that only tests them (`props.children ? <div>{props.children}</div> : …`, `!props.children`, `props.children != null`, `Boolean(props.children)`) checks whether the slot exists instead of rendering it. Two Vue differences remain: a slot exists, and tests truthy, whenever the caller writes nested children, even when they render nothing, and `{...props}` does not forward nested children, so pass them on explicitly (`<Card {...props}>{props.children}</Card>`). The editor's type view still shows `props.children` as written.
