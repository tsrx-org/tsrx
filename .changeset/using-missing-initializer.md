A `using` or `await using` declaration's name without an initializer is now TypeScript's TS1155 `'using' declarations must be initialized.` on the name, as for a `const` one: a strict compile throws it, and a collecting or loose compile records it and reads on, so the editor keeps the file. It was acorn's error at the token after the name, thrown in every mode (`using x;`, `await using x;`, `for (using of;;) {}`). After `declare`, which makes the declaration ambient to TypeScript, there is none: `declare using x;` is TS1491 on `declare` alone, as in TypeScript. A missing initializer inside a `using` declaration's binding pattern now comes after the pattern's TS1492, and after a modifier's error before it (`abstract using {x} = y, z;`), as TypeScript reports them. TS1155 on a name written with an escape (`const \u0078;`) now covers the whole name. The Prettier plugin rejects a `using` declaration without an initializer, as Prettier's `typescript` parser does, where it formats a `const` one, and `declare` before a `using` or `await using` declaration in a block (TS1184), which it printed without the `declare` (`{ declare using x = y; }` became `{ using x = y; }`).
