---
'@tsrx/core': patch
---

A compound selector with `:root` or `:host` no longer gets the scope hash, whatever else it has. `:root.dark .icon` in a component compiled to `:root.dark.<hash> .icon:where(.<hash>)` whenever `.icon` had an ancestor element in the component, and always in an assigned block, so the rule needed `<html>` to carry the hash and never applied; `:root.dark { --c: … }` compiled to `:root.dark.<hash>` everywhere. These now compile as `:root` alone does: `:root.dark .icon.<hash>`, `:root.dark { --c: … }`, `:host.open .icon.<hash>`. In an assigned block, `:root` and `:host` alone no longer take the class bump either, so `:root .icon` gives `:root .icon.<hash>`, as in a component. A bare `:global` list beside such a compound (`:global.w, :root.dark`) is no longer `TSRX3011`, since neither is scoped. A selector whose `:root` or `:host` compound has a `:has()` none of whose arguments matches an element of the component is now pruned, as other selectors with such a `:has()` are: `:root:has(.missing)` compiled to `:root:has(/* (unused) .missing*/)`, an empty `:has()`, which is invalid and made the browser drop the whole selector list (`:root:has(.missing), .icon` lost `.icon`). A rule with an animation whose selector has only such compounds (`:root.dark:has(.icon)`) now gets the hash on its `:has()` arguments when no element matches it, as any other animation rule no element matches does; `:root:has(.missing) { animation: … }` was kept unscoped.
