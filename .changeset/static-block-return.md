A `return` right in a class `static` block, also in a block or a loop there, is now TypeScript's checker error for it, `TS18041` (`A 'return' statement cannot be used inside a class static block.`), at the `return`. A strict compile throws it, as it threw `TS1108` before. A collecting compile and the editor record it and read on, where the parse stopped there, so the editor lost the rest of the file's diagnostics; the editor now shows TypeScript's own `TS18041` there. A `return` in a template in a `static` block keeps its template error, and one in a class in a template is the class's. As in TypeScript, a `return` isn't reported in the operand of a `return` that is (or of one outside a function, which TSRX allows at the top level), nor in a parameter default that TypeScript doesn't check (`TS2371`), and the first statement of a block in an ambient class's `static` block is left to TypeScript's `TS1036`, as any statement there is. A `return` right in a namespace is still `TS1108`.
