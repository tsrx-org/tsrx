Report a namespace or module declared outside the module's or a namespace's body, in a function, block, `if`, loop, label, `case`, static block or template body, as TypeScript does: TS1235 (`A namespace declaration is only allowed at the top level of a namespace or module.`), or TS1234 (`An ambient module declaration is only allowed at the top level in a file.`) for `module "m"` or `global`, at the declaration's first token (after a leading `abstract`, which the output leaves out, at the token after it, where the editor shows TypeScript's own error). A strict parse throws it before the checker errors in the declaration. A syntax error, an error a strict parse can't read past (such as a rest parameter that isn't last), or one that ends every parse (such as a `break` with nowhere to go) still comes first, as before. The compile used to report nothing and emit output that doesn't parse. After `export` in a block, `global` and `module "m"` are TS1234 too, where they were TS1184 or TS1235, and `declare` or `abstract` before one there is no longer reported on its own. The editor's code maps the declaration's first token, so the editor shows TypeScript's own error there, once. With it mapped, the editor also shows TypeScript's TS1540 deprecation hint on `module M {}`, as in a .ts file. An import or export in a block is reported on its whole `import` or `export` keyword, as TypeScript reports it, so the editor shows that once too, also in an arrow's default parameter.
