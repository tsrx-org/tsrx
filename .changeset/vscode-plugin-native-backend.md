'@tsrx/vscode-plugin': minor

Add native TypeScript 7 support. The extension never asks which TypeScript VS Code runs: no setting of its own, no lookup of other extensions. With TypeScript 7 on, TypeScript 7 runs `@tsrx/content-mapper` for the `.tsrx` files each `tsconfig.json` declares under `contentMappers`, and the extension no longer patches the built-in TypeScript extension and runs the TSRX language server without its TypeScript services; with it off, the classic backend runs unchanged. The extension now also activates when a single `.tsrx` file is opened and declares that it does not run in untrusted workspaces. Migration and rollback steps, the compatibility matrix against the classic path, and benchmarks are in `packages/content-mapper/ROLLOUT.md`, `COMPATIBILITY.md` and `BENCHMARKS.md`. The extension no longer bundles TypeScript: on the classic backend the language server hosts the TypeScript VS Code runs for the workspace (the version chosen with "TypeScript: Select TypeScript Version", read from `js/ts.tsdk.path` or VS Code's own copy), and follows a change of that choice by restarting the language server. With TypeScript 7 off, VS Code's own tsserver serves `.tsrx` files through `@tsrx/typescript-plugin`, which the extension now contributes as a tsserver plugin (`typescriptServerPlugins`, with `languages: ["tsrx"]`) and ships: the built-in TypeScript extension is no longer patched, `.ts` importers resolve `.tsrx` modules with VS Code's own TypeScript and no tsconfig `plugins` entry, VS Code's own TypeScript commands and menus work on `.tsrx` files, and the extension neither bundles nor hosts any TypeScript. The TSRX language server always runs slim and reports TSRX compile errors; the extension drops that copy for a file the content mapper already reports on, so compile errors show once under TypeScript 7 as well. On the first `.tsrx` file of a directory the extension opens the nearest `.ts` or `.js` file hidden, because VS Code's TypeScript extensions activate only on JavaScript and TypeScript documents and TypeScript 7 loads the project declaring the mapper only once a file of it is open (microsoft/TypeScript#64355). A project with no `.ts` or `.js` file at all gets a self-explaining `tsrx-wake-up.ts` written next to the `.tsrx` file and opened as an inactive tab beside it, which the extension closes and deletes as soon as TypeScript reports on it. The workaround goes away with the upstream fix (tsrx-org/tsrx#138).
