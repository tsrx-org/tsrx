'@tsrx/hono': patch
---

Hono DOM no longer reports `Hono JSX DOM does not support async components` for a component registry that reaches code the check does not follow, which can replace its async member before render. Passing the registry to a function (`patch(UI)`) or constructor, calling a method on it that isn't an arrow function (`UI.init()`), storing it in an object, array or member (`{ ui: UI }`, `[UI]`, `holder.ui = UI`), passing it as a component prop or returning it now counts as possibly replacing its members, as a write through an alias already did; `Object.values`, `Object.entries`, `Object.getOwnPropertyDescriptor` and `Object.freeze` hand on its members, so they count as possibly replacing members of those. So does a write through an object or array that holds it (`box.ui.App = …`, `list[0].App = …`), a `for…of` variable, or a parameter or destructuring default. An async member is still reported when its registry is only read, copied with a spread or rest element, passed to a built-in that doesn't write, keep or return any of it (`console.log`, `JSON.stringify` without a function replacer, `Object.keys` and similar), called through an arrow-function member (`UI.App()`), or when only the member's own value is passed on (`memo(UI.App)`). A write to a property of an async component (`App.displayName = …`, `Object.assign(App, …)`) no longer hides it.
