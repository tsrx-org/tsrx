Add `tsrx/no-useless-assignment`, ESLint's `no-useless-assignment` with the blocks of a `@try` as alternatives ([#1289](https://github.com/tsrx-org/tsrx/issues/1289)). Code path analysis runs the blocks one after another, so the core rule reported a value that the body overwrites though `@pending` or the `@catch` reads it, or a value the body assigns and the `@catch` assigns again though the code after the `@try` reads it. The compiled output runs the blocks in callbacks, and the `@catch` or `@pending` can render without the blocks before them. The TSRX rule drops a report of the core rule only when letting each block, and the code after the `@try`, also start from the start of the `@try` or from the end of any block before it makes the value used; it reports nothing the core rule doesn't, and in a file without `@try` it is the core rule. It keeps the core rule's answers for a `@try` whose body or `@pending` awaits or yields, and for a `@try` where code path analysis follows more than one path at once, as in a `finally` block that a `throw` or a `return` can enter, and still reports a value read only in a block that code path analysis holds unreachable, such as a `@catch` after a body that throws, or only in a block that runs again after a later one, such as the body after `reset()`.

On ESLint 10, whose `js.configs.recommended` turns on `no-useless-assignment`, `tsrx.configs.js` turns it off for `.tsrx` files and turns on `tsrx/no-useless-assignment` at `error`. On ESLint 9 the `js` configuration is unchanged.
