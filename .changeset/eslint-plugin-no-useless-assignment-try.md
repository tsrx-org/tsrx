Add `tsrx/no-useless-assignment`, ESLint's `no-useless-assignment` with the blocks of a `@try` as alternatives ([#1289](https://github.com/tsrx-org/tsrx/issues/1289)). Code path analysis runs the blocks one after another, so the core rule reported a value that the body overwrites though `@pending` or the `@catch` reads it, or a value the body assigns and the `@catch` assigns again, which the code after the `@try` reads when the `@catch` doesn't render. The compiled output runs the blocks in callbacks, and the `@catch` or `@pending` can render without the blocks before them. The TSRX rule drops a report of the core rule only when letting each block, and the code after the `@try`, also start from the start of the `@try` or from the end of any block before it makes the value used; it reports nothing the core rule doesn't, and in a file without `@try` it is the core rule. It keeps the core rule's answers for a `@try` whose body or `@pending` awaits or yields, and for a `@try` where code path analysis follows more than one path at once, as in a `finally` block that a `throw` or a `return` can enter, and for a `@try` where code path analysis goes on to code that doesn't follow it (a `@switch` arm before the last, or the last when an earlier arm assigns; the body of a `@for` with `@empty`, or `@empty` when the loop assigns; an attribute value; a `@for`'s index or key; a destructuring default), and still reports a value read only in a block that code path analysis holds unreachable, such as a `@catch` after a body that throws, or only in a block that runs again after a later one, such as the body after `reset()`. The added starts mix two orders, the code after a `@try` running before its blocks (React, Preact, Hono) or after them (Solid, Vue), so the rule can drop a report that holds on every target: across two `@try`s on one path (siblings, or one inside another's block), and with one `@try` when the body assigns a value before anything that can throw, the `@catch` reads the value from before the `@try`, and either the code after the `@try` assigns it again on every path or nothing renders the `@try`; and when an element after the `@try` reads the value in an attribute and assigns it in its children, since Solid and Vue set attributes after children. When a block always ends in a `throw`, the rule adds no starts for that `@try`. On Hono, a `@pending` that neither awaits nor yields runs in the component, before the body and the code after the `@try`; the rule doesn't know the target, so it can drop the report of a value such a `@pending` overwrites.

On ESLint 10, whose `js.configs.recommended` turns on `no-useless-assignment`, `tsrx.configs.js` turns it off for `.tsrx` files and turns on `tsrx/no-useless-assignment` at `error`. On ESLint 9 the `js` configuration is unchanged; if you turn on `no-useless-assignment` there, use `tsrx/no-useless-assignment` for `.tsrx` files instead.
