On React, Preact and Hono, a fragment whose elements are all hoisted already is now hoisted as one module-level constant, instead of being built around one constant per element on every render (#1352). `export function B() { return <><div> 1 </div>{<><div> 2 </div><div> 3 </div></>}</>; }` gave three constants and built both fragments again on every render; it now gives one `const B__static1 = <>…</>;` and `return B__static1;`. A fragment is hoisted when it holds at least one hoisted element, and each of its other children is text, a literal, or a fragment of these. That covers a component's output, the output of a render helper or of an `@if`, `@switch`, `@try` or `@for` body, and a fragment in an expression container or an attribute value. The fragment is hoisted as the component printed it in place, so its text renders the same markup. It takes in no element that wasn't hoisted already, so every element is built when it was before, and no component inside the fragment renders less often. A memoized component that receives the fragment as a prop or as children can skip a render, as it can for a single hoisted element since 0.6.0. A row of a keyed `@for` keeps its key and stays in place. Solid, Vue and Hono DOM don't hoist, and their output is unchanged.
