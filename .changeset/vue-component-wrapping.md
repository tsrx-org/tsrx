More Vue components are now wrapped in `defineVaporComponent`, and wrapped components can be read above their declaration:

- An arrow component that contains a nested function, such as an inline `onClick={() => …}` handler or a `.map()` callback, is now wrapped. Before, it stayed a plain function, and mounting it as the app root threw `Cannot read properties of undefined (reading 'config')`.
- A component that builds its JSX in a local variable and returns it (`const element = <div />; return element;`) is now wrapped. Before, its props never reached it and mounting it as the app root threw. A local binding counts when it holds JSX anywhere, the same rule already used for a returned expression, so a `function Config() { const c = { icon: <i /> }; return c; }` is wrapped just as `function Columns() { return [{ header: <b /> }]; }` already was.
- A default-exported component (`export default function Card`) now compiles to `const Card = defineVaporComponent(…); export default Card;`, so the module keeps its `Card` binding. Before, one with a nested function compiled to the invalid `export default const …`, and `typeof Card` or `export { Card }` lost the binding.
- A component read above its declaration while the module loads, as in `export const registry = { inner: Inner }` before `function Inner`, now loads: the compiler moves the wrapped `const` above that read when doing so changes nothing else. When the component's destructured prop defaults read a binding that the statements it would move past declare, assign or mutate (vue-jsx-vapor evaluates `{ label = PREFIX }` when the component is defined), the compiler reports the new TSRX2028 at the read and asks you to move the declaration up instead. Reads that do not run at load (in a function, a class instance field, a branch a constant condition skips, or a scope with its own binding of the name) move nothing. Calls are not followed: a read through a call or IIFE still hits the constant before it is initialized, and a call in between to a function that assigns a binding a default reads (`bump()` setting `size`) runs after the moved component captured the old value; reads from another `case` of the declaring `switch` or through a circular import cannot be seen either.
- A destructured prop default that vue-jsx-vapor would silently drop now reports the new TSRX2029 at the default. vue-jsx-vapor turns those defaults into prop options and keeps only a string, number, boolean or `null` literal, an identifier, an object or array literal, or a function, so `{ s = cfg.size }`, `-1`, `SIZE + 1`, a call or a template literal left the prop `undefined` when the caller left it out. This applies to every wrapped component, including ones wrapped before this change; read the prop in the body instead (`const s = props.s ?? cfg.size`).
