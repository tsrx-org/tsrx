The TSRX language server no longer floods the VS Code extension host with file events in a large workspace ([#1084](https://github.com/tsrx-org/tsrx/issues/1084)). It watched every TypeScript, JavaScript and JSON file, `node_modules` included, and vscode-languageclient holds file events until none has arrived for 250 ms, so dev servers that write files all the time grew that queue without limit. Beside the editor's TypeScript (the `plugin` and `native` backends), the server now watches only `.tsrx` files, JSON files, lockfiles and the files package managers write at the end of an install. The extension no longer sends events from `node_modules` or a framework build directory (`.next`, `.nuxt`, `.output`, `.svelte-kit`, `.turbo`, `.vercel`), except TypeScript configs and the files that show an install finished. A `package.json` in those directories, such as the one Vite writes in `node_modules/.vite/deps`, no longer restarts the server. An install still does, also when `git pull` changed the lockfile before it: through the install markers (`node_modules/.modules.yaml`, `.package-lock.json`, `.yarn-state.yml`, `.yarn-integrity`) and the `package.json` of each package installed directly in `node_modules`. A restart waits until package files have stopped changing for a second, and at most ten seconds.
