On React, Preact and Hono, a static element inside an expression container is now hoisted to a module-level constant, like a static element written bare. `<>{<div> 123 </div>}</>` hoisted nothing before; now the inner `<div>` gets its own constant (#81). This covers a container in an element's or a fragment's children, in an attribute value such as `<Card header={<h1>Title</h1>} />`, in either branch of `?:`, on the right of `&&`, `||` and `??`, and in a nested container, including in the JSX that a render helper or callback in the component body returns, whose bare statics were already hoisted. In a branch that may not render, only host elements such as `<span>` are hoisted, so a component like `<ui.Button />` in `{show && <ui.Button />}` is still read only when it renders, never when the module loads. A static fragment in a container keeps its children, each hoisted on its own, and consecutive statics are not merged into one fragment, so the children React sees keep their shape. An element with a `key`, JSX that reads a binding, a bare child of a dynamic element, and JSX inside a function or array within a container (such as `{items.map(() => <li />)}`) stay in place. A static's name now skips any name the module source already uses, so an authored `App__static1`, in the component or at module level, can't redeclare it or capture its references. Solid, Vue and Hono DOM output is unchanged, since those targets don't hoist.
