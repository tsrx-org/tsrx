'@tsrx/vue-runtime': patch

On the Vue target, a `@try` now shows its `@catch` for an error its body's own inline code throws after the first render: an expression that throws on an update, such as `{props.item.price.amount}` once `price` is gone, or an event handler written in the body. Before, Vue passed such an error over the `@try`, because that code belongs to the boundary that renders the body, and Vue starts at that instance's parent. The error went to `app.config.errorHandler` while the body kept its last output, or a `@try` inside another one's body lost it to the outer `@catch`; the same code in a child component was caught. Each boundary now puts a hook first among its parent's error hooks, and that hook takes the errors the boundary itself is the source of while it shows its content. Some still go on as before: what the `@catch`'s own inline code throws, what the body throws while the `@try` unmounts, and what it throws while a `Suspense` around the `@try` is still pending, also in the branch a `Suspense` keeps showing while a new one loads, where swapping in the `@catch` could unmount a component the `Suspense` waits for.
