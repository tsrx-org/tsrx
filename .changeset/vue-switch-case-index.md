On the Vue target, a `@for` row that is a `@switch` and renders through `VaporFor` now follows its value: in a keyed loop without `@empty` whose head has no default, computed key or object rest, and in a loop without a key whose row reads the item's properties (a destructured head without a key is read once, as before). Those other loops render through `map_iterable`, which already followed the value. The `VaporFor` row slot ran the `@switch`'s IIFE once, so the row kept the case it picked first, and threw `Cannot read properties of null (reading 'anchor')` when no case matched. The row now makes a `computed` that runs the `switch` for the index of the case it picks, and renders the case chosen by that index in a fragment, which vue-jsx-vapor makes `createIf`s: the row follows its value, keeps its case mounted while the index stays the same, and renders nothing when no case matches. A throw from the discriminant or a case test reaches Vue's error handling, or an `@catch` around the loop, and the row follows its value again once it stops throwing. A row whose `@switch` has no cases runs its discriminant whenever what it reads changes.

A row keeps the shared lowering when a case of its `@switch` has setup statements, or renders anything but an element, a fragment, nothing or a choice of them, such as a nested `@switch`: as a branch of its own, such a case would render again, components and all, whenever its item is replaced. A fragment around a single expression is that expression, so a case like `<>{row.title}</>` keeps the shared lowering too, and a row still can't mount it, as before. So does a row whose `@switch` has more than 64 cases. A `@switch` elsewhere, a `@switch` row in a loop with `@empty` (which stays on `map_iterable`), one that awaits or yields, and the type-only output keep the shared lowering. `@tsrx/core` exports it as `switchStatementToJsxChild` for a platform's `controlFlow.switchStatement` hook.
