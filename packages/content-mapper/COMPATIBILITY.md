# Compatibility matrix: classic versus native TypeScript

Every observed difference between the classic path (`tsrx-tsc` and the TSRX
language server hosting TypeScript 5 through Volar) and the native path
(TypeScript 7 `tsc --runExternalCode` and `tsc --lsp` through
`@tsrx/content-mapper`), classified. Phase 4 of
[tsrx-org/tsrx#41](https://github.com/tsrx-org/tsrx/issues/41).

Observed on 2026-09-18 with TypeScript 7.1.0-dev.20260918.1 (native) and
TypeScript 5.9.3 (classic), Node 24.18, macOS 15 x64, from the sources at the end
of Phase 3 plus the Phase 4 harness. "Evidence" names the test or probe that pins
the row; probes are one-off scripts run for this matrix, tests run under
`pnpm test --project content-mapper`.

## Classification

| Class                   | Meaning                                                                                                |
| ----------------------- | ------------------------------------------------------------------------------------------------------ |
| **no difference**       | Same result on both paths.                                                                             |
| **compiler-version**    | TypeScript 7 and TypeScript 5 behave differently on the same input; not caused by the mapper.          |
| **previously hidden**   | A real diagnostic the classic path dropped and the native path reports.                                |
| **adapter bug, fixed**  | A defect in the TSRX transform or mapper found during the work and fixed on both paths.                |
| **adapter design**      | An intentional difference in how the mapper presents the same information.                             |
| **upstream limitation** | A gap in the content-mapper protocol or TypeScript 7 that the mapper cannot work around; issue linked. |
| **client requirement**  | Works when the editor or LSP client supports what TypeScript 7 needs; nothing to fix in TSRX.          |
| **untested**            | Not exercised yet; listed so the gap is explicit.                                                      |

## Not yet exercised

Listed against the validation matrix of the issue so the next pass can close them:

- **Resolution**: `paths` aliases and monorepo symlinks beyond the test
  workspaces' junctioned `node_modules`; `.tsx` importers of `.tsrx` modules.
- **Editors**: inlay hints with hints enabled; which formatter VS Code picks for
  `.tsrx` now that TypeScript 7 registers one; CSS features inside `<style>` on
  the native backend in a real editor (only the service-plugin list is pinned).
- **Lifecycle**: deleting and renaming `.tsrx` files during a native session; more
  than one mapper-backed project in one `tsc --build` graph.
- **Packaging**: the published `@tsrx/content-mapper` tarball and the VSIX outside
  this checkout, on Linux and Windows (only macOS x64 has been run).
- **Third-party compiler fixture** under the language server (only the CLI is
  covered).
